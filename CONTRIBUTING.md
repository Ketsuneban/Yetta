# Contributing to Yetta

Yetta is currently in the specification and website phase. Contributions should preserve the documented security boundaries and must not imply that planned features are already implemented.

## Before opening a pull request

1. Describe the user-visible change and its motivation.
2. Keep changes focused and document new project decisions.
3. Do not add credentials, API keys, personal data, private certificates, or local secrets.
4. For security-sensitive proposals, explain the threat model and failure behavior.
5. Validate HTML, CSS, JavaScript, JSON, and links affected by the change.

## Versioning

The website and documentation use semantic versioning when a tagged project release is introduced. During the initial infrastructure phase, changes are tracked in `CHANGELOG.md` and Git history. Do not invent application release numbers before the application exists.
