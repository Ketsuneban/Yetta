# Иконки причины и тесты предупреждений

Набор `src/Yetta.Desktop/Assets/Causes` отделён от иконок шапки и навигации. Оригинальные SVG сохранены; для WPF подготовлены PNG 384×384 без изменения исходных PNG (100×100). Иконка причины не зависит от уровня предупреждения, в том числе Fatal, Agreement и Dax.

| ID | Причина |
|---|---|
| 1 | Python-файл (.py, .pyw) |
| 2 | Важный пользовательский файл |
| 3 | Текстовый файл / документ |
| 4 | Защищённый файл |
| 5 | Исполняемый файл / скрипт |
| 6 | Tallow |
| 7 | Windows как система |
| 8 | Облачный файл без локальных данных |
| 9 | Папка |
| 10 | Архив |
| 11 | Приложение без собственной иконки |
| 12 | Неизвестная причина / файл без расширения |
| 13 | Фото, видео, аудио |
| 14 | Конфигурация Windows |
| 15 | Yetta |
| 16 | DAX |

Приложение указывается явно через `WarningCauseType.Application`; наличие расширения .exe само по себе не превращает файл в приложение. Собственный значок берётся из ресурсов исполняемого файла; при отсутствии используется 11. Иконка зарегистрированного редактора не подменяет иконку документа.

Приоритет файлов: облачный placeholder → папка → конфигурация Windows → защита → важность → расширение → 12. Метаданные облака: Offline, RecallOnOpen, RecallOnDataAccess; HTTP(S) источник также считается облачным. Файлы не открываются для чтения содержимого, загрузки или выполнения.

Защита определяется по System/ReadOnly/Encrypted, расположению в Windows, владельцу TrustedInstaller и явным ACL-запретам записи/удаления для текущего пользователя и его групп. Это наблюдаемые признаки, а не гарантия обнаружения защиты стороннего продукта. Windows-конфигурация: .reg, файлы .ini/.cfg/.conf/.config/.xml/.json внутри Windows и системный hosts; обычный JSON приложения не считается конфигурацией Windows.

Важность — документ или медиафайл в Документах, на Рабочем столе, в Изображениях, Музыке или Видео, включая подпапки. Это правило интерфейса; содержимое не анализируется. Защита и системная конфигурация имеют приоритет над важностью.

## Marvine

```text
/test warn <Standard|Information|Caution|Dangerous|Critical|Fatal|Agreement|Dax> <причина> [pass:true/false] [tty:true/false] [check:true/false] ["текст"]
```

Причина: Yetta, DAX, Tallow, Windows, путь к файлу/папке или HTTP(S) URL. Пути с пробелами заключаются в двойные кавычки. Для приложения используйте `"app:C:\Path With Spaces\Application.exe"`. Обычный путь всегда обозначает конкретный файл, даже если это .exe или .py.

```text
/test warn Caution "C:\Work\script.py" pass:false tty:false check:true "Проверка Python-файла"
/test warn Critical DAX pass:true tty:true check:true "Проверка всех полей"
/test warn Fatal Tallow pass:false tty:false check:false "Тест фатального окна"
```

`pass:true` включает поле с демонстрационным паролем **test**, подписанным в окне; пароль Windows не запрашивается. `tty:true` требует действующий локальный TTY. `check:true` включает галочку. В тестах флаги задают поля точно, включая Critical и Fatal; правила настоящих предупреждений не ослабляются. Тест ничего не запускает и не восстанавливает; Fatal сохраняет приоритет в очереди. Закрытие окна и отклонение не означают согласие. Пароли и введённый TTY не попадают в историю Marvine.


С версии 0.4.2 параметры pass, tty, check необязательны и допускаются в любом порядке; по умолчанию все false. Без текста используется тестовое описание. Без причины используется Yetta. Например: `/test warn Standard Yetta` или `/test warn Caution "C:\Work\script.py" check:true`. Все тестовые окна имеют кнопки «Разрешить» и «Запретить».
