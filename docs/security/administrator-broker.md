# DAX Administrator: привилегированный брокер (рабочая ветка, не выпущено)

## Статус

Исходники добавлены в ветку разработки. **Этот компонент не опубликован и не проходил
Windows-сборку, проверку в реальной ОС или независимый аудит безопасности.**
Не используйте его с важными системами до завершения проверки и подписания бинарников.

## Как работает

1. Yetta запускается с обычным токеном пользователя.
2. При установке профиля **Администратор** Yetta показывает описание возможностей.
3. После согласия Windows отображает **настоящий UAC** на запуск отдельного
   `Yetta.AdminBroker.exe --install <SID>`. Yetta не отключает и не имитирует UAC.
4. Установщик копирует брокер в защищённую директорию
   `%ProgramFiles%\Yetta\AdminBroker\` и создаёт службу `YettaAdminBroker`
   под LocalSystem. Разрешённый SID сохраняется в защищённом HKLM.
5. Yetta соединяется с локальным именованным каналом, сначала проверяет PID
   сервера по зарегистрированной Windows-службе (SCM), затем получает ответ.
6. Служба принимает сообщения только от одобренного SID с настроенным ACL
   и проверкой impersonation; неизвестные операции запрещает.

Это предоставляет реальное выполнение **строго определённых** действий
с повышенными правами *внутри службы*. Нажатие профиля не меняет токен
главного процесса и не повышает права PowerShell/сторонних приложений.

## Первые операции (строгий белый список)

- `ping` — проверить службу и права текущего клиента.
- `read-machine-proof` — прочитать состояние настройки Yetta в HKLM.
- `write-machine-proof` — записать проверочную дату только в
  `HKLM\SOFTWARE\Yetta\AdminBroker\LastProofUtc`.
- `clear-machine-proof` — удалить только это проверочное значение.

Никакие пути, ключи реестра, командные строки, PowerShell или исполняемые
файлы не передаются клиентом в качестве параметров. Успешные операции
модификации записываются в защищённый раздел
`HKLM\SOFTWARE\Yetta\AdminBroker\Audit`.

## Отзыв прав

DAX Guard → «Отозвать права и удалить службу». Для удаления Windows
выдаёт отдельный запрос UAC. После этого профиль возвращается в USER
или GUEST, а защищённые операции недоступны. Если Yetta уже удалена,
администратор может удалить службу системными средствами Windows.

## Важно для выпуска

- Служба под LocalSystem — критически привилегированный компонент.
  Нужен обязательный ручной threat-model/code-review и тесты для
  подмены клиента/сервера IPC, разных Windows SID, отказа UAC,
  остановленной/поддельной службы и работы на Windows 10/11.
- Перед публичным распространением необходима **проверяемая цифровая
  подпись издателя** (EXE, helper, installer) и гарантированная установка
  из доверенного источника. SHA-256 рядом с бинарником — не
  аутентификация издателя.
- Публикация обновлений Yetta в `%LOCALAPPDATA%` **не должна**
  обновлять SYSTEM-службу. Новые версии брокера требуют отдельной
  подписанной привилегированной операции.
- Стандартный защитный режим Windows «Administrator protection» может
  дополнительно ограничивать длительное повышение прав; требуется
  отдельно проверить на актуальных сборках Windows 11.
- Независимо от пользовательского согласия нельзя подавлять UAC
  для посторонних программ или выполнять неизвестные команды от SYSTEM.

Это ограниченный функциональный прототип, не готовая универсальная
административная платформа и не замена механизмам защиты Windows.
